# Route field-service guidance across model vendors

```bash
npm install
INFRAI_API_KEY=your_key npm run dev
```

Open a second terminal and run:

```bash
npm run demo
```

This service takes a work-order photo assessment, current dispatch state, technician follow-up, and urgency. Infrai gives you one OpenAI-compatible `baseURL`; `model: "auto"` sends the guidance request across model vendors, so this service stays free of vendor-specific branches.

## The request that matters

`POST /dispatch-decision` checks the full JSON body with zod before any model call happens:

```json
{
  "workOrderId": "WO-1042",
  "photos": [{ "label": "pump housing", "observation": "Active leak beneath the inlet coupling" }],
  "dispatchStatus": "unassigned",
  "technicianFollowUp": "Bring isolation kit and confirm shutoff access.",
  "urgency": "urgent"
}
```

Expected result: `action` is `expedite_dispatch`, and `modelGuidance` holds the short technician instruction generated by the routed model.

The dispatch rule itself stays deterministic in local code. The model is only used to write the field instruction. It does not decide if an urgent unassigned job gets escalated. That keeps the operational state transition easy to test and keeps work-order identifiers out of the prompt.

## Verify the decision

```bash
npm test
npm run typecheck
```

This focused test sends an urgent, unassigned work order and asserts both the escalation decision and the action included in the model prompt.

## Privacy boundary

Only send the observations needed for dispatch, not raw patient, resident, or customer records. In this example, photo findings are converted to text before the model call, and the work-order identifier is left out of that prompt. For regulated deployments, apply the same minimum-necessary rule to technician notes and logs too.

The main gotcha is simple: failover should not own the business decision. Keep dispatch policy deterministic, then use routed model output for wording and follow-up guidance.
